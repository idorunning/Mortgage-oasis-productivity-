# Mortgage Oasis — commission dashboard

A local dashboard that tracks commission, makes outstanding money obvious,
chases it to paid, and reconciles the **Tracker** against the weekly
**consolidation statements**. It runs on your own computer and refreshes itself
from Google — **client data never leaves your machine except to talk to your own
Google account.** It is never hosted on a public website.

## Quick start (Windows)

1. Do the one-time Google connection in **[SETUP-WINDOWS.md](SETUP-WINDOWS.md)**
   (~10 min).
2. Double-click **`run-dashboard.bat`**. It opens the dashboard in your browser.
3. Click **Refresh from Google** to pull the latest Tracker + statements.

After that, refreshing is one click whenever you edit the Tracker or drop new
statement files into the Statements folder.

## How the data flows (and why it's private)

```
Google Drive ──(Google API, your credentials)──► your PC ──► data/*.json ──► dashboard in your browser
```

`server.py` runs a tiny web server on `127.0.0.1` (your machine only — not
reachable from the internet or your office network). Its **Refresh from Google**
button runs `scripts/gdrive_refresh.py`, which signs in to *your* Google account
and downloads the Tracker sheet and the statement workbooks straight to local
JSON. Nothing is sent to Claude/Anthropic or any third party.

## The dashboard

Tabs, all filterable by year (top-right):

- **Commission chasing** (the landing view) — a hero **"Outstanding to chase"**
  figure with 30/60/90+ day aging; a **Chase worklist** of everything awaiting
  commission (sort biggest-first or oldest-first) with inline **Chase** buttons
  on overdue cases; a **Tracker vs statements** table showing predicted vs paid
  with the shortfall; and a **Needs review** section for payments the matcher
  isn't sure about. Two sliders — *Overdue after* and *Variance threshold* —
  apply across the dashboard and are remembered per device.
- **Overview** — KPI tiles and charts (written vs received, statement income,
  business-type and provider breakdowns).
- **Commission tracker** — every Business Register case, searchable and
  filterable. "Written" = predicted commission; "Received" = what came in.
- **Recurring income** — monthly NI (non-indemnity) and R (recurring trail)
  totals; GI hidden behind an "Include GI" toggle. (Statement classes:
  M = mortgage, I = insurance, NI = non-indemnity, R = recurring.)
- **Statements** — weekly consolidation statements with monthly totals and
  expandable line items.

### Matching & chasing

Statement payments are matched to Tracker cases automatically (by client
surname, provider, amount and date). A case shows as **Paid** once a statement
match or the Tracker's Commission Received lands. The **Chase** button opens a
**Gmail compose** window pre-filled with a formal chase (client, reference,
provider, amount due, days outstanding) — it **never sends**; you press Send.
After chasing, the row shows *Chased <date> · follow up <date + 1 week>*, then
becomes **Follow up due** / **Chase again** once the week passes. Chase history
is stored per device (localStorage), like the sliders. The recipient address is
`CHASE_TO` near the top of the chase section in `admin/assets/app.js`.

## Structure

| Path | What it is |
|---|---|
| `run-dashboard.bat` | Windows launcher (sets up the environment, starts the server) |
| `server.py` | Local `127.0.0.1` server + `/api/refresh` |
| `admin/` | The dashboard (HTML/CSS/JS, no libraries) |
| `data/*.json` | Local data, regenerated by refresh — **not committed** (see below) |
| `scripts/gdrive_refresh.py` | Pulls Tracker + statements from Google |
| `scripts/statement_parser.py` | Parses one statement workbook |
| `scripts/extract_tracker.py` | Parses the Tracker sheet |
| `scripts/merge_statements.py` | De-duplicates + merges statements |
| `scripts/build_local.py` | Optional: bundle everything into one offline HTML file |

## Client data is not in the repo

`data/tracker.json`, `data/statements.json` and the built
`MortgageOasis-Dashboard.html` contain client names, addresses and commission
amounts, so they are **git-ignored** — the repository holds code only, and the
data is regenerated on your machine by the refresh. (They still exist in the
history of earlier commits in this private repo; ask if you want that scrubbed.)

## Offline single-file build (optional)

For a portable snapshot with no server:

```bash
python3 scripts/build_local.py     # -> MortgageOasis-Dashboard.html
```

Double-click it — works offline, no refresh button. It's a point-in-time copy;
rebuild it after a refresh. Open it as a local file (Drive's web preview doesn't
run JavaScript; use Drive for desktop and open the synced copy).

## Manual refresh (without the button)

```bash
python3 scripts/gdrive_refresh.py            # uses config.json
```

Or rebuild from a downloaded Tracker `.xlsx` and pre-parsed statement JSON:

```bash
python3 scripts/extract_tracker.py Tracker.xlsx data/tracker.json
python3 scripts/merge_statements.py statements_2024.json statements_2025.json statements_2026.json -o data/statements.json
```

If a new year tab is added to the Tracker (e.g. "Business Register 2027"), add
its column layout to `LAYOUTS` in `scripts/extract_tracker.py`.

## ⚠️ Never host this publicly

Do not deploy the dashboard or its data to any public website. It is designed to
run locally only. If hosting is ever reconsidered it must come with
hosting-level access control on the whole site (a client-side password alone is
not enough — the JSON would still be downloadable).
